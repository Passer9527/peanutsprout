```text
Phase 0 文档与工程骨架
   │
   ├──► Phase 1 连接与 SQL 开发闭环 ──► Phase 3 可视化看板 ──┐
   │            │                                            ├──► Phase 5 多平台打包与自动更新
```

- Phase 1 是后续所有阶段的前置：对象树、元数据、结果集、事务控制是所有能力的地基。
- Phase 2 依赖 Phase 1 的连接管理与 SQL 执行能力。
- Phase 3 依赖 Phase 1 的结果集与连接能力；与 Phase 2 可并行推进。
- Phase 4 依赖 Phase 1（元数据 + 执行）与 Phase 3（结果集展示）；脱敏与确认链路必须与能力同批交付。
- Phase 5 依赖前四期的功能稳定；打包本身不新增业务功能。

## Phase 1 连接与 SQL 开发闭环

**目标**：让用户在一个连接上完成「连得上、看得见对象、写得动 SQL、改得动数据」的完整日常开发闭环。

### 范围

| 方向 | 内容 |
| --- | --- |
| 连接增强 | 连接分组、标签、搜索、收藏；连接串 URL 解析；云数据库快捷模板；SSH 隧道、SSL/TLS、代理；连接池与超时心跳；驱动版本管理与自定义驱动加载；只读保护、生产库颜色标识 |
| 权限完善 | 按连接/库/表/操作类型的资源级授权鉴权链路；会话隔离与超时自动锁定；修改密码、找回密码、可选 2FA |
| 对象与 SQL | 对象树完整层级与搜索/过滤/跳转；SQL 编辑器（语法高亮、智能补全、多标签、多光标、折叠、格式化）；执行计划可视化；慢 SQL 标记 |
| 结果与数据 | 结果集分页/流式加载、单元格编辑、多格式导出（CSV/Excel/JSON/SQL/Markdown）；表设计器与 DDL 预览；数据编辑器（批量替换/删除/插入、校验、事务回滚） |
| 界面与服务 | 桌面端与 Web 端界面完善（可拖拽布局、主题、快捷键、全局搜索、新手引导）；服务端多用户会话隔离、WebSocket 进度推送；定时任务调度框架 |

### 对应模块编号

M01-03、M01-04、M01-07、M02-02、M02-04、M02-05、M02-06、M02-07、M03-06、M03-08、M03-09、M04-01、M04-02、M04-03、M04-05、M04-07、M04-08、M04-09、M04-12、M04-14、M08-02、M08-05、M08-07、M09-06、M10-02、M10-04、M11-03、M11-04

### 验收口径

1. **AC-05 满足**：普通用户仅能看到授权连接，`DELETE` 等写操作被拒绝并留痕；`resource_grants` 授权链路端到端可验证。
2. **AC-07 的连接配置部分满足**：桌面端与 Web 端读取同一份连接配置，修改后双向可见（看板部分留待 Phase 3）。
3. `NFR-5.1-02` 连接建立 ≤ 2 秒；`NFR-5.1-03` 结果集 10 万行以内不卡顿（分页/流式生效）。
4. `FR-4.7-03` 常用操作不超过 2 次点击；快捷键可自定义；会话中断后可恢复。
5. 连接密码、SSH/SSL 配置全部以 AES-256-GCM 加密落库，明文不落盘、不进日志。

### 风险

| 编号 | 风险 | 应对 |
| --- | --- | --- |
| P1-R1 | SSH 隧道 / SSL / 代理组合场景复杂，易出现「能连但不能用」 | 分场景做连通性矩阵测试；连接测试给出分层诊断（网络/握手/鉴权/权限） |
| P1-R2 | 大结果集流式加载与内存上限冲突（`NFR-5.1-05` 正常使用 ≤ 2GB） | 游标分批拉取、按需渲染、导出走流式而非全量驻留 |
| P1-R3 | 对象树 / 元数据抽取在不同数据库差异大 | 以 `MetadataProvider` 统一抽象，SQLite 先行验证，其余库按 Phase 2 逐步补齐 |
| P1-R4 | 只读保护被绕过（例如通过存储过程或 DDL 间接写） | 只读判定下沉到执行引擎与驱动层，不只做 UI 禁用；写操作强制二次确认 |
| P1-R5 | SQL 智能补全的元数据缓存过期，补全结果与实际结构不符 | 补全缓存带版本与失效策略，结构变更后主动失效 |

## Phase 2 导入导出与异构迁移

**目标**：打通「文件 ↔ 数据库」与「数据库 ↔ 数据库」的双向数据流动，落地本产品的核心差异化能力。

### 范围

| 方向 | 内容 |
| --- | --- |
| 导入 | CSV/Excel/JSON/XML/SQL 脚本/Parquet；来源含本地文件、剪贴板、另一数据库、URL；可视化拖拽字段映射；类型自动推断 + 手动覆盖；去重、过滤、脱敏、格式转换；批量提交、断点续传、失败重试 |
| 导出 | CSV/Excel/JSON/XML/SQL/Parquet/Markdown/PDF；范围含整库、整表、查询结果、选中行；定时导出、增量导出 |
| 异构迁移 | 源库→目标库自动类型映射；表结构自动迁移；全量 + 增量数据迁移；迁移前预检；迁移报告；支持双向 |
| 数据同步 | 一次性、定时、增量同步；冲突策略含覆盖、跳过、报错、人工确认 |
| 驱动落地 | MySQL、MariaDB、PostgreSQL、Oracle、SQL Server、金仓、达梦、OceanBase、TiDB 等真实驱动适配；跨库类型映射表；各库 DDL 方言；执行计划解析 |
| 支撑能力 | 多用户连接池服务；导入导出文件上传下载；迁移结果落库（`migrations`、`migration_checkpoints`、`migration_errors`）；CDC（视库能力） |

### 对应模块编号

M02-05、M03-02、M03-03、M03-04、M03-05、M03-07、M05-01～M05-11、M09-07、M10-03、M10-05、M11-03

### 验收口径

1. **AC-02 满足**：同时连接 MySQL 与 PostgreSQL，单表结构 + 数据迁移成功，类型自动映射，报告显示成功条数。
2. `NFR-5.1-04` 100 万行级别导入导出可完成；`NFR-5.3-02` 迁移失败可回滚。
3. 迁移报告包含成功/失败/跳过统计与失败原因明细，失败明细可按行定位（`migration_errors`）。
4. 断点续传可验证：中断迁移后执行 `resume`，从检查点继续而非重头开始。
5. 跨库类型映射遵循「尽力映射 + 人工确认」（RK-01）：预检报告明确列出高风险映射，需用户确认后才执行。

### 风险

| 编号 | 风险 | 应对 |
| --- | --- | --- |
| P2-R1 | 跨库类型映射无法 100% 完美（RK-01） | 预检报告 + 人工确认 + 迁移后可核对报告，不做「静默转换」 |
| P2-R2 | 部分数据库驱动存在许可证限制（RK-05） | 驱动选型阶段做法务确认；优先使用许可证宽松的驱动，必要时改为可选下载 |
| P2-R3 | 大表迁移的内存与事务压力，长事务导致源库锁表 | 分批提交 + 可配置批大小 + 限流；默认避开业务高峰，提供只读快照/无锁读选项 |
| P2-R4 | 字符集与排序规则不一致导致数据损坏（`NFR-5.4-03`） | 预检阶段检测字符集差异；迁移强制显式字符集转换并记录日志 |
| P2-R5 | CDC 能力因数据库而异，实现复杂度高 | 明确 CDC 为「视库能力」的可选能力，未支持的库降级为定时增量同步（M05-10） |

| 数据与配置 | 表/视图/查询结果绑定；维度、指标、聚合方式手动配置 |
| 交互 | 图表联动、下钻、筛选；保存为看板；看板布局与分享 |
| 刷新与导出 | 手动刷新、定时刷新、WebSocket 推送；导出图片、PDF |
| 关联能力 | ER 图（自动生成、布局、导出图片/SQL）；数据对比（两表/两库差异） |

### 对应模块编号

M04-11、M04-13、M06-01～M06-08、M09-06、M10-04

### 验收口径

1. **AC-03 满足**：对订单表生成折线图、条形图、平行坐标图，并成功保存为看板。
2. **AC-07 完成**：Web 端与桌面端看到同一份连接配置**和**同一份看板；看板配置落库（`dashboards` / `charts`）并在重新登录后保持。

### 风险

| 编号 | 风险 | 应对 |
| --- | --- | --- |
| P3-R1 | 大结果集直接渲染导致浏览器卡顿 | 聚合下推到数据库执行，前端只取聚合结果；超出阈值时提示抽样 |
| P3-R2 | 平行坐标、桑基、树图、地图等复杂图表实现成本高 | 按「高频优先」排序：折线/柱状/饼/散点先行，复杂图表与地图为可选增强 |
| P3-R3 | 看板分享链接泄露数据 | `share_token` 可撤销 + 有效期；分享默认只读；敏感字段按脱敏规则处理（SR-02） |
| P3-R4 | WebSocket 定时刷新在多用户并发下放大数据库压力（`NFR-5.1-06`） | 刷新间隔下限 + 结果缓存 + 并发连接数限制 |

## Phase 4 AI 助手

**目标**：接入大模型辅助库/表/字段/数据管理，并在「安全可控、可完全禁用」的前提下交付。

### 范围

| 方向 | 内容 |
| --- | --- |
| 模型接入 | OpenAI、Anthropic、Google、通义千问、文心一言、智谱、DeepSeek、本地 Ollama 等；支持私有化部署模型 |
| 模型配置 | API Key（AES-256-GCM 加密）、模型名、温度、超时；多配置与默认配置 |
| AI 能力 | 自然语言转 SQL、SQL 解释、SQL 优化建议、库/表/字段管理助手、数据操作助手（DML 需二次确认）、数据问答、文档生成（数据字典）、错误诊断 |
| 安全与可控 | AI 生成的 SQL/DML 必须经用户确认才执行；生产库默认禁止 AI 直接执行写操作；敏感字段脱敏后再发给大模型；支持完全禁用 AI；所有 AI 操作记入审计日志 |
| 记录 | AI 调用历史落库（`ai_history`：场景、提示词、响应、token 数、耗时、状态） |

### 对应模块编号

M07-01～M07-12、M09-06、M08-08（AI 操作审计）

### 验收口径

1. **AC-04 满足**：输入「查最近 7 天订单金额前 10 的用户」，AI 生成 SQL，用户确认后执行并返回结果。
2. 生产库 AI 写操作 100% 被拦截；任何 AI 生成的 SQL/DML 未确认前不得执行。
3. 脱敏网关默认开启且可配置：敏感字段在发送给大模型前完成脱敏（SR-02、FR-4.5-03）。
4. AI 功能可一键完全禁用（SR-04）；禁用后界面与服务端均不发起任何模型请求。
5. 每一次 AI 调用均可在审计日志与 `ai_history` 中检索到操作人、场景、耗时与结果状态。

### 风险

| 编号 | 风险 | 应对 |
| --- | --- | --- |
| P4-R1 | AI 生成的 SQL 存在错误甚至破坏性风险（RK-02） | 强制人工确认 + 语法/影响面预检 + 生产库禁写 + 禁止自动执行多语句 |
| P4-R2 | 提示词注入（库表注释、数据内容中携带恶意指令） | 系统提示与数据内容严格分离；工具调用白名单；对模型输出做 SQL 静态校验 |
| P4-R3 | API Key 泄露或随日志外泄 | Key 以 AES-256-GCM 加密落库，日志脱敏，界面不回显明文 |
| P4-R4 | 模型超时、限流、成本不可控 | 超时与重试可配置；记录 token 用量；提供调用频次与成本上限 |
| P4-R5 | 私有化部署模型接口不兼容 OpenAI 协议 | 以 provider 适配层隔离差异，OpenAI 兼容协议优先（如 Ollama、vLLM） |

## Phase 5 多平台打包与自动更新

**目标**：产出「安装即用、零环境依赖」的六种平台/架构安装包，并建立发布与自动更新通道。

### 范围

| 方向 | 内容 |
| --- | --- |
| 运行时与驱动内置 | 内置 Node.js 运行时（随 Electron 打包）；内置数据库驱动随包分发 |
| 安装包 | Windows x86_64 / arm64（NSIS 或 MSI `.exe`）；Linux x86_64 / arm64（`.deb` / `.rpm` / AppImage）；macOS x86_64 / arm64（`.dmg` / `.pkg`），命名遵循 `PeanutSprout-Setup-{version}-{os}-{arch}.{ext}` |
| 签名与公证 | Windows 代码签名；macOS 代码签名与公证；Linux 包签名 |
| 持续集成 | 多平台构建与测试流水线；版本号与变更记录自动化 |
| 发布与更新 | 发布渠道（官网、GitHub Releases）；自动更新（版本检查、增量/全量更新、离线包）；诊断包一键导出 |
| 运维与合规 | 独立服务端部署（二进制 / Docker）、反向代理与负载均衡适配；备份恢复；发布前协议与说明文件复核（`LICENSE`、`README.md` 已在 Phase 0 交付，`CHANGELOG.md`、`CONTRIBUTING.md`、`CLA.md` 已就位）；SSO 与消息通知（可选） |
